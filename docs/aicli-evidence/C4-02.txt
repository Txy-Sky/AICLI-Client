三、实现要点与口径（详见第 13 节偏差记录）
- 接缝：EnsureProxyFn / RuntimeRefreshFn 注入，生产实现分别调 ProxyService
  is_running/start 与代理运行时 AicliRuntime::refresh（拉取→编译含默认配置集在内
  的全部配置集→批量 ensure Token）；测试注入假实现，不真占用固定端口。
- 目标选择 takeover::bind_targets：首次绑定（aicli_takeover 无行）= 已安装的全部
  Tier 1；非首次 = 该表现有行 ∩ Tier 1。已安装以配置目录判定（Desktop 用
  detect_installed），绑定路径不跑 shell 探测。
- 自动接管固定 confirmed=false：检测到 cc-switch 残留时该项记 cc_switch_conflict，
  交由 C3-11 既有手动确认流程。
- aicli_bind 返回 AicliBindResult（account 视图 + proxyStarted/proxyError/
  runtimeRefreshError + 逐项 takeovers）；事件名 aicli-takeover-results，负载同结构。
- 失败注入位置：客户端配置读写阶段（config.toml 被目录占用），断言逐项独立与不回滚。

提交：73de4dc1 fix(aicli): C4-02 never widen takeover on unreadable targets

一、读接管目标失败不扩大范围（aicli/takeover.rs）
- 修正前：bind_targets 用 .ok()/unwrap_or_default() 吞掉锁中毒与 SQL 错误，读表失败
  得到空列表，被当成首次绑定，接管全部已安装 Tier 1，越过用户此前的选择。
- 修正后：bind_targets 返回 Result；失败时 bind 一个都不接管，错误记入
  AicliBindResult.takeover_targets_error（事件负载 takeoverTargetsError），绑定不回滚。
二、账户视图失败不丢逐项结果（commands/aicli.rs）
- 修正前：末尾 self.get_account()? 在代理已启动、客户端已接管之后失败，命令整体报错，
  逐项结果不返回、事件不发。
- 修正后：AicliBindResult.account 改 Option，失败时为 None 并记 account_error（错误码）；
  逐项结果照常返回并下发。前端尚未调用 aicli_bind，C5 runner 只用 takeovers，无破坏面。
- 去掉多余的 takeovers.clone()。
