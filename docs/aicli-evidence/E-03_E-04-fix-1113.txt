## 2. 全小写 sk- 密钥（E-03，9312ff43）

现象：sk- 规则的 ok 判断 not_a_slug 不是 Magpie 的 notASlug，而是另一套启发式（数字挨大写、
或连续 8 个辅音）。全小写的密钥——DeepSeek 的 sk- 加 32 位十六进制、OpenRouter 的 sk-or-v1- 加
64 位、小写的 sk-ant-api03-…——都判为普通词，前面没有 api_key=、*_KEY= 之类字段名时原样上发。
E-03 的 522 条 golden 对照没有暴露：语料里 20 条 sk- 样本都带大写字母。
修复：not_a_slug 按 Magpie redact.go 的 notASlug 逐行移植（含大写，或 sk- 后只剩十六进制，或
连字符/下划线之间 16 位以上）；Magpie 的两处调用（sk- 规则、skill 名判断）在这里也是这两处。
SK hynix 文章地址这类小写单词串仍不遮。
测试：fieldvalue::tests::not_a_slug_matches_magpie（每条判据与反例）、
redact::tests::lower_case_sk_keys_masked_and_slugs_kept（三种密钥在纯文本里遮盖，文章地址保留）。

## 3. keepalive 冲掉扣留的半个占位符（E-05，a75853cb）

现象：流式还原扣留以占位符开头结尾的事件，等同一路径的下一段拼接。中间夹一个 keepalive
（Anthropic 的 ping，模型慢时会夹在工具参数中间；Responses 的 keepalive、response.in_progress、
response.queued）时，因上下文不同，扣留段带着半个占位符原样放出，下一段带着另一半，两段都
还原不了。经 Claude Code 的 Write/Edit 会把 {{SECRET_…}} 或孤立的 { 写进用户文件。
修复：移植 Magpie 76f00399c（MIT，#5287）：这类事件先放出，扣留段继续等下文。Chat 的
keepalive 是 SSE 注释行，本来就在事件之间原样透传；Gemini 没有 keepalive。
测试：stream::tests::placeholder_held_across_keepalive，移植 Magpie TestWriterHeldAcrossKeepalive：
Anthropic input_json_delta 夹 ping、Responses function_call_arguments.delta 与
custom_tool_call_input.delta 夹 response.in_progress，占位符内部每个字节位置切开；客户端拼出的
参数含真实值，三个事件都输出。
