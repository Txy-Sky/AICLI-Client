## 一、E-07 Maskit 黑盒对照（仅开发机）

### 1. 边界（AGPL）

- Maskit 是 AGPL-3.0。**只当黑盒跑，不读它的代码、正则、规则表和测试夹具**，更不要复制或翻译进仓库（清单 E-01「禁止」、第 0.6 节第 18 条）。
- 它只放在仓库外运行。清单写的是 `/root/maskit-reference`；Windows 开发机用任意仓库外的目录也可以，在证据里写明实际路径。
- 仓库里只提交两样东西：`scripts/aicli-poc/maskit_diff.py`（我方编写），和 `docs/aicli-evidence/E-07.md`（差异统计与结论）。证据里不贴 Maskit 的规则原文；需要举例时，用我方语料里的值。
- Maskit 不进 CI 工作流，也不进产物。

### 2. 推荐的对照方式：反向代理 + 捕获上游

Maskit 本身就是反向代理（README：OpenAI 协议 `127.0.0.1:18701/v1`，Anthropic 协议 `127.0.0.1:18703`，控制台 `5801`）。可以用官方 Docker 镜像、Release 安装包，或者源码启动，任选一种。

```
maskit_diff.py ──POST──▶ Maskit :18701/v1/chat/completions ──▶ 本地捕获服务（记录收到的 body，回一个固定 JSON）
```

- 在 Maskit 控制台里，把上游 Base URL 指向 `maskit_diff.py` 自己起的本地捕获服务，不连任何真实上游。
- 每条语料放进 `messages[0].content` 发送一次，从捕获到的 body 里取出 content，就是 Maskit 对这条语料的输出。
- 我方输出：复用 E-03 的 `redact::tests::write_rust_raw_for_golden_diff`（`#[ignore]`，固定密钥，`Options{secrets, personal}`），或者另写一个同样的 `#[ignore]` 导出测试，生成 `target/rust_raw.txt`。
- **规则开关要写清楚**：Maskit 默认只开 7 类，另外 14 类（PEM 私钥、JWT、云 AccessKey、IP 等）需要手动开。请**全部打开**跑一遍，用来找我方漏遮；如果时间允许，再用默认配置跑一遍做参考。证据里写明两次各自的配置。

### 3. 差异怎么算

两边占位符的格式不同，不能直接逐字节比较。

- 按「被替换掉的原文片段」比较：对每条语料，用 `difflib.SequenceMatcher` 分别找出两边输出相对原文被替换的片段（start、end、原文）。我方的类别从 `{{KIND_xxxxxxxx}}` 里取；Maskit 的类别从它的占位符文字里取，取不到就记为 `unknown`。
- 每个片段归入四类之一：两边都遮、只有我方遮、只有对方遮、范围不同（有重叠但边界不一致）。
- **[验收]** 清单要求「每一类差异都有结论」。只有对方遮的片段，要逐个归为三种之一：
  - **我方漏遮**：修复，或者说明为什么不修；
  - **对方误报**：给出理由，例如订单号、哈希、普通数字；
  - **口径不同**：例如对方连键名一起遮、对方遮内网 IP、边界取法不同。
- **[验收]** **我方漏遮的密钥类、证件类条目必须修复后才能通过。**手机、邮箱、IP 这类可以给出「不修」的理由。

### 4. 语料

- E-03 的 `corpus.jsonl`（522 条，只有 `text` 字段，没有类别标注）可以直接用。但它是按 Magpie 的规则写的，覆盖不到 Maskit 宣称的部分类别。
- 请**自写**补充语料，覆盖：数据库连接串（`postgres://user:pass@host/db`、`mongodb+srv://…`、JDBC）、座机号码（含区号和分机）、PEM 私钥块、云 AccessKey（阿里云 `LTAI…`、AWS `AKIA…` 加 secret）、各类 IP、JWT、`.env` 片段、代码里的硬编码凭证。**不得从 Maskit 的测试或文档里复制样例。**
- **语料中的假密钥要用脚本在运行时生成**，不要手写在文件或对话里。E-03 证据记录过：执行环境的本地网关会把模型写出的敏感值替换成 `{{TAG_xxx}}`，`corpus.jsonl` 和 Magpie 源码参考都因此被污染过。写完语料后，用脚本检查文件里没有 `{{`、`TAG_` 这类占位符，再提交。

### 5. 修复漏遮会带来的连锁变化

- 新增规则会超出「逐条移植 Magpie」的范围，所以要在第 12 节偏差表单列一行：写明新增了哪些规则、为什么需要（E-07 的哪一类漏遮）。规则文件头注明「我方新增，非 Magpie 移植」。
- E-03 的 golden 对照（522 条与 Go 逐字节一致）会因此出现差异。**不要改 golden 或放宽断言**（第 0.2 节第 7 条）。正确做法是：新规则单独放进一个类别或一张规则表，golden 对照时关掉；或者给每条差异写明豁免原因。同时补 `expected.json` 和 `false_positives.json` 的用例。
- 每条新规则都要有误报用例：订单号、UUID、提交哈希、版本号、文件路径不被遮。
- 跑一遍 `E-03-fuzz` 和 `E-04-unit`，确认新规则不会产生 panic，也不会破坏 JSON 结构。

### 6. 跑不起来时

Maskit 起不来（例如依赖装不上、Docker 不可用）时，标 `[!]`，在第 12 节写明原因和尝试过的方法。这**不阻塞 E-GATE**。不要为了凑结果去读它的代码。

### 7. 测试与提交

- 新增规则的单元测试加入 `E-03-unit` 组（已在 `scripts/aicli-item-tests.sh`）。`maskit_diff.py` 只在本机运行，不进 CI。
- 提交：`feat(aicli): E-07 …`（规则修复）、`docs(aicli): E-07 record …`（证据）。

## 二、E-08 中文姓名（可选开关，默认关闭）

### 1. 来源与授权

- Magpie @ `f11bf27c`：`internal/redact/zhname.go`（487 行）、`zhdict.txt`（约 1500 词，来自 jieba，MIT）、`zhname_test.go`。`THIRD_PARTY_NOTICES.md` 已有 jieba 声明（E-01），词典文件头保留来源说明，用 `include_str!` 嵌入。
- 文件头注明来源和 commit，与 E-03 的做法一致。

### 2. 脱离模型怎么接线（最容易错的地方）

- 在 Magpie 里，`zhNameSpans(s, person, nicks)` 只在模型路径里调用（`model.go` 约 92～98 行）：`person` 是模型找到的人名，`nicks=o.NamesByModel`。
- 我方没有模型。开关打开时，调用方式等价于 **`zhNameSpans(s, person=[], nicks=false)`**，并且只在 `personal` 类别开启时生效（对应 Magpie 的 `o.covers(catPersonal)`）。
- `zhname_test.go` 里依赖模型的用例**不能**照搬，要逐条列出并说明原因（清单 E-03 的同类要求），包括：`TestChineseNamesByModelOnlyNicks`、`TestModelWordsAreNoNames`、`TestModelNamesBesideWords`，以及 `TestChineseNamesNeedModel` 中「没有模型就不遮」那半句（我方语义是「开关打开就遮」）。`TestChineseNames`、`TestChineseWordsAreNoNames`、`TestMaoliIsAMargin` 这类规则本身的用例，用 `person=[]` 移植。
- 占位符类别用 `PERSON`。确认 `engine.kinds()` 能包含它，这样流式还原的裸词尾部（word_tail）才能识别 `{{PERSON_` 开头的半截占位符。补一条流式测试：姓名占位符被切在两个事件之间时，客户端最后收到原名。

### 3. 「遮过一次就一直遮」

- `known.rs` 会记住遮过的值，进程内共享，之后在任何文本里再出现都会被遮。门槛是 `MIN_KNOWN = 8` 字节：两个字的名字（6 字节）不会被记住，三个字的名字（9 字节）会。
- 结果是：一个三个字的误报（例如被误判为人名的普通词），会在之后所有请求里继续被遮。
- **[验收]** 精确率评估必须分两种方式各跑一遍：
  - 每条语料用一个新引擎（单条精确率）；
  - 全部语料共用一个引擎、按顺序处理（反映真实会话里的累积误报）。
  两个结果都写进证据，**以较低的那个和 95% 比较**。

### 4. 设置项 `privacy_detect_cjk_names`

- 存储：`aicli_account` 的列定义在 `aicli/schema.rs`，当前 `SCHEMA_VERSION = 25`。加一列，需要沿用仓库现有的升级方式（参考 `REQUEST_LOG_COLUMNS` 的幂等加列，或者版本迁移），并且通过 C1-03 的 schema 测试：旧库升级后原有行逐字节不变。
  - 如果必须提升 `SCHEMA_VERSION`，属于数据结构变化，按第 0.3 节第 3 条先标 `[!]` 问负责人，不要自行决定。
- 读取：与 E-06 的三个隐私设置一样，进入 `PrivacySettings` 内存缓存，由 `aicli_get_privacy`/`aicli_set_privacy` 读写，提交后调用 `bump_revision()`。`PrivacyGate::mask_request` 构造 `MaskOptions` 时带上它。热路径不查库。
- 默认值 `0`（关闭）。

### 5. 语料与评估

- **[验收]** 至少 200 条自写中文语料，带标注：每条列出应被遮的姓名（可以为空）。存放在 `src-tauri/tests/fixtures/privacy/zhname_corpus.jsonl`，格式例如 `{"text": "...", "names": ["…"]}`。
- 要有足够多的**反例**（不含人名，但含有以姓氏字开头的词），否则精确率没有意义：`王国`、`张开`、`文案`、`毛利率`、`黄绿色`、`关键词`、`应用层`、`高兴`、`边界`、`建国路`、`江山`、`方圆`、`常用`、`林业`。正反例比例写进证据。
- 正例要覆盖各种提示语境：角色（`客户`、`联系人：`、`我叫`）、动词（`给…发`、`问一下`）、称谓（`先生`、`老师`、`说`）、并列（`李娜和刘洋`）、复姓（`欧阳`、`司马`）、昵称（`小王`、`老李`）。
- **姓名同样会被执行环境的本地网关替换**。请用脚本从「姓氏表 × 名字用字」组合生成正例，生成后检查文件里没有 `{{`；不要手写真人的名字。
- 指标按片段计算：TP 是遮盖范围与标注完全一致；范围不一致记为 FP + FN。精确率 = TP/(TP+FP)，召回率 = TP/(TP+FN)。评估脚本和结果都要提交。

### 6. 不达标时

**[验收]** 精确率低于 95%（按第 3 小节较低的那个值）：代码保留，开关隐藏（不出现在 `aicli_get_privacy` 的返回里，或者返回 `available: false`，供 F-06 判断是否显示），数值写进第 12 节。不要为了达标而删反例或放宽标注。

### 7. 测试与提交

- 新增 `item E-08-unit aicli::privacy::rules::zhname`（文件名按实际情况）；设置项读写的测试并入 C3-11-unit（`commands::aicli::tests`）或 E-06-unit 的现有组，并在证据里写明。
- 提交：`feat(aicli): E-08 …`、`docs(aicli): E-08 record …`。

## 三、加快进度的建议

### 1. E-GATE 可以提前跑（需要负责人决定）

- E-GATE 的验收条件只有三条：**E-01～E-06 全部 `[x]`**、`scripts/aicli-check.sh` 通过、用真实 Claude Code（H-02）在隐私开启下完成一轮多轮对话。**不包含 E-07、E-08**，而且这三条现在都已具备：H-02 已由负责人指定为执行端的 Windows 本机，C5-GATE 也是这样做的。

- 同意后，F 阶段可以提前约两到三个工作日开始。E-08 的开关界面在 F-06 实现，F-06 排在 F 阶段末尾，届时 E-08 早已完成，不会冲突。

### 2. 提交前自查（来自 E-06 的三轮打回）

E-06 的三轮打回，有一半是同一类问题：**测试证明的情况，不是真实会出问题的情况**。提交前请逐条检查：

- **故障注入点要放在真实会失败的位置**：注入点比真实 panic 点早一步，就测不出状态丢失（E-06 第二、三轮都是这个原因）。
- **测试夹具不能让被测条件自动成立或自动失败**：E-06 的「全链路串行化」结论，最可能来自 mock 的全局模式开关。第二个请求也拿到挂起的流，看起来就像被串行了。
- **做一次变异验证**：把修复去掉，测试必须失败。证据里写一句「去掉修复后 X 测试失败」。
- **声称「既有问题、非本次引入」时，要提交最小复现**（测试或脚本），不能只写结论。
- 测试数据含多字节字符和块边界，并且至少切一次在字符中间。

### 3. 本地先跑通再推送

每推一次，完整 CI 大约 15～20 分钟。推送前至少在本机跑：

```
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
cargo nextest run --manifest-path src-tauri/Cargo.toml aicli::privacy
cargo nextest run --manifest-path src-tauri/Cargo.toml --features test-hooks aicli::privacy::stream::tests::fa
```

只改了 `docs/**` 的提交不触发 CI（`paths-ignore`），证据可以随时补提交。
