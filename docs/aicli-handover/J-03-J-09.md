# J-03～J-09 真实客户端验收交接（执行端）

清单 `### J-02～J-10`。J-03 OpenClaw、J-04 Hermes、J-05 Pi、J-06 MCode、J-07 Kimi、
J-08 DSH、J-09 OMP 的验收 1、2（配置里没有 `sk-` 和访问令牌、还原逐字节一致）已由 CI
单测验收（`docs/aicli-evidence/J-03_J-10.txt`）。本交接只做**第 3 条**，并在真实环境里
复核 1、2：

> 3. 安装该客户端的真实版本，发一个文本请求和一个工具调用请求，经代理成功，
>    `proxy_request_logs` 中 `app_type` 正确。

J-10 Agy 不在本交接里：Agy 只从进程环境变量读服务地址和密钥，没有可接管的配置文件，
结论是「暂不支持接管」（第 12 节）。

## 前提：界面入口

这 7 个客户端目前**只有后端**，「客户端」页仍显示「即将支持」、没有接管按钮（清单规定
真实客户端通过后才提供）。J-02 时负责人决定先开放按钮再验收；这 7 个是否照此办理要
负责人决定。开放之前，执行端可以用 CI 产物里的开发构建，或等开放按钮的提交。

## 做法

与 `docs/aicli-handover/J-02.md` 完全相同（隔离 HOME、准备一份自己的配置并记 SHA-256、
接管、文本请求、工具调用请求、查 `proxy_request_logs`、用量页、停止接管后比对哈希、
删掉配置后再接管和停止）。每个客户端单独做一遍，结果分别记录。

各客户端被改写的文件（都在隔离 HOME 下；有对应环境变量时以环境变量为准）：

| 编号 | 客户端 | 接管写入的位置 | 写入内容 |
|---|---|---|---|
| J-03 | OpenClaw | `~/.openclaw/openclaw.json` | `models.providers.aicli`：`baseUrl`、`apiKey`（本地令牌）、`api: openai-completions`、模型列表 |
| J-04 | Hermes | Hermes 配置目录的 `config.yaml`（`HERMES_HOME`） | 提供方 `aicli`：`base_url`、`api_key`、模型 |
| J-05 | Pi | `~/.pi/agent/models.json` | `providers.aicli`：`baseUrl`、`apiKey`、`api: openai-completions`、模型 |
| J-06 | MCode | `~/.minimax/config.yaml`（`MINIMAX_DATA_DIR`） | 提供方 `aicli`：`options.baseURL`、`options.apiKey`、模型 |
| J-07 | Kimi Code | `~/.kimi-code/config.toml`（`KIMI_CODE_HOME`） | `aicli` 提供方及 `aicli/<模型>` 条目 |
| J-08 | DSH | `~/.dsh/profiles/{web,desktop,headless,acp}/cordis.patch.yml`（已存在的那些）和 `~/.dsh/.credentials.yaml`（`DSH_HOME`） | 每个 profile 的 `llm-pi-ai` 下加提供方 `aicli`；本地令牌只写进凭据文件，profile 里只留引用 |
| J-09 | OMP | OMP 当前 profile 的 `models.yml` | `providers.aicli`：`baseUrl`、`apiKey`、`api: openai-completions`、模型 |

所有客户端的地址都是 `http://127.0.0.1:<代理端口>/app/<客户端>/v1`，协议为 Chat
Completions；`apiKey` 是本地令牌 `aicli-local-…`，不是上游密钥。不改客户端的默认模型。

请求时在客户端里选 `aicli` 提供方下的模型（DSH、OMP、Pi、Kimi 的模型名带 `aicli/` 前缀
或在提供方列表里选 AICLI）。第 6 步查询时 `app_type` 应分别是 `openclaw`、`hermes`、
`pi`、`mcode`、`kimi`、`dsh`、`omp`。

## 结果怎么记

- `docs/aicli-evidence/J-0N-real.txt`（每个客户端一份）：环境（系统、提交、客户端版本与
  安装方式、隔离方式）、逐步结果、SQL 结果。截图放 `docs/aicli-evidence/J-0N/`。
- 打码规则同 J-02。提交标题带对应编号。

## 通过与不通过

- **全部符合期望**：清单对应行改为 `[x]`；第 12 节「J-03～J-09（真实客户端）」一行
  注明哪些已关闭。
- **任何一步不符合**：保持 `[!]`，把现象和报错原文写进 `J-0N-real.txt` 交回审查方。
  审查方修复，或把该客户端从 `aicli/tier.rs` 的 `TIER2_SUPPORTED` 去掉、界面保持「暂不
  支持」。不得往配置里写真实密钥来绕过。

## 已知限制（遇到不算失败，但请注明）

同 J-02：只支持 Gemini 端点的模型请求时返回 `capability_unsupported`；关闭本地路由后
已接管的客户端请求会失败；本地统计对这些客户端的输入 token 按「不含缓存」计（第 12 节
「J-01 期间观察」）。
